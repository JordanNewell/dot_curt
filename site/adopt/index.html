Make your app speak .curt.

The format is free — the move is yours. One afternoon of work buys your users a conversation file that never loses anything and never goes stale.

Why implement it

  • Full fidelity — base64 images and tool calls ride in content, verbatim. No flattening, no “best effort”.
  • Unknown fields survive a re-save. Your app's extras aren't a liability.
  • One diffable UTF-8 file per conversation. Archives, version control, and grep all just work.
  • MIT across the board — spec, reference code, schema, fixtures. (Curtis applications themselves are BUSL; the format never is.)

The path

Four steps. Conformance is testable at every one.

  1. Install. npm i curt-format — serializeCurt, parseCurt, curtFilename.
  2. Round-trip. Serialize a conversation, parse it back, confirm unknown fields survive. That's the L1 bar.
  3. Prove it. Run the conformance vectors — L1 CORE, L2 NAMED, L3 BULK, L4 per-extension. 27 vectors, plain fixtures, CI-runnable.
  4. Get listed. PR against capabilities.json + CAPABILITIES.md: who you are, what you read/write, which extensions, conformance level. Public and checkable.

Questions, answered

  • Will the spec change under me? No. Core is frozen at v1. Evolution is registry-only.
  • Who decides? One maintainer, BDFL. Deliberately — a format with six committees has no direction.
  • What does draft mean for me? Emit it if you want; readers must reject unknown extensions cleanly, so nothing breaks.
  • License? MIT — spec, implementation, schema, fixtures. Build a business on it if you like.
